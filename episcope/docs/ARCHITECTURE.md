# EpiScope Architecture

EpiScope is a modular platform for retrieval‑augmented question answering and
structured information extraction from academic papers.  It exposes two
primary modes:

* **Explorer** – embed all papers in a project and answer general
  questions using a vector database and a language model.  Explorer is
  implemented via retrieval–augmented generation (RAG) and supports
  multiple retrieval strategies.

* **PrecisionMiner** – perform deep per‑paper parsing and structured
  extraction using GROBID, OCR for scanned PDFs and a suite of
  extractors (paper classifier, table extractor, reference extractor,
  LLM extractor).  PrecisionMiner outputs structured JSON files and
  builds per‑paper FAISS indices for efficient querying.

The repository is laid out to cleanly separate concerns.  The top‑level
packages are:

```text
configs/      # configuration modules and defaults
src/          # FastAPI service exposing ingest and query endpoints
core/         # shared abstractions: RAG base class, provider interfaces, provenance models
ingest/       # ingestion pipelines for PDFs and DOIs
parse/        # PrecisionMiner implementation (blueprints, extraction, indexing, processing, querying)
index/        # wrappers for vector storage backends (e.g. Qdrant)
retrieve/     # RAG implementations (text only, multimodal, graph) and factory
generate/     # answer generator orchestrating retrieval, LLM and provenance
providers/    # pluggable LLM provider implementations (local/Ollama, OpenAI, Gemini)
projects/     # per‑project data storage (empty by default)
storage/      # persistent storage (indices, snapshots, etc.)
ui/           # simple Streamlit UI for evidence‑first exploration
cli/          # Typer‑based command line interface
utils/        # common utilities (logging, etc.)
tests/        # pytest suite (currently minimal)
docs/         # documentation
```

## Explorer (RAG) Pipeline

Explorer implements retrieval‑augmented generation over plain text.
The `TextRAG` class (in `retrieve/rag/text.py`) extracts text from PDFs
using `unstructured.partition.pdf`, generates dense, sparse and late
interaction embeddings, stores them in Qdrant via the `UnifiedQdrantIndex`
and retrieves the most relevant contexts for a user query.  An answer
is then generated by an LLM provider, and provenance metadata is
attached to each answer.

Additional retrieval strategies (e.g. ColPali and GraphRAG) can be
implemented and registered via `retrieve/rag/factory.py`.

## PrecisionMiner Pipeline

The `parse/` package contains the full implementation of the
PrecisionMiner pipeline.  It consists of:

* **Blueprints** (`parse/blueprints`) – data models and Pydantic
  schemas describing structured sections, references and extraction
  results.
* **Configs** (`parse/configs`) – configuration classes controlling
  search parameters and pipeline behaviour.
* **Extraction** (`parse/extraction`) – modules for paper
  classification and LLM‑driven information extraction.
* **Processing** (`parse/processing`) – pipeline orchestrating GROBID
  parsing, figure/table extraction and concurrent execution.
* **Indexing** (`parse/indexing`) – FAISS‑based indexing of
  structured chunks for efficient retrieval.
* **Querying** (`parse/querying`) – HyDE query generation and RAG
  querying over structured chunks.
* **Utils** (`parse/utils`) – helpers for serialization and caching.

The PrecisionMiner pipeline currently mirrors the functionality of
`source_extraction_mod` in the original repository but has been
repackaged under `parse/` for clarity.  Future work will further
refactor and test these modules.

## Logging and Configuration

Global configuration is defined in `settings.py` using Pydantic
`BaseSettings`.  The `ProviderConfig` controls which LLM provider is
used (``local``, ``openai`` or ``gemini``) and which model to invoke.
The `IndexConfig` defines the Qdrant collection and connection
parameters.  These settings can be overridden via environment
variables.

Logging is configured centrally in `utils/logger.py`.  The log level
can be adjusted by setting the ``EPISCOPE_LOG_LEVEL`` environment
variable.

## Provenance

Every answer returned by EpiScope includes a `Provenance` object
containing the answer and a list of `Evidence` objects.  Each evidence
record specifies the paper identifier, a snippet of supporting text,
the section type, and metadata about the index version and model used.
This transparency enables traceability and auditability of all answers.
